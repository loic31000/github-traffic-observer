# Privacy

GitHub Traffic Observer is designed for **aggregate repository observability**, not person-level tracking.

## What GitHub Traffic provides

Depending on the endpoint, GitHub exposes aggregate counts, GitHub-reported unique counts, top referrers and top popular paths.

The collector does not receive a visitor's GitHub account identity, IP address, browser fingerprint, cookies, personal profile, or exact per-person browsing history.

## Rules for this project

1. **Private by default.** Store real collected data in a private repository.
2. **No deanonymization.** Do not infer that a specific named person generated a visit or clone.
3. **No cross-service identity correlation.** A social referrer and a GitHub visit do not prove they came from the same person.
4. **No fingerprinting.** Do not add tracking pixels, cookies, IP logging or browser/device fingerprinting.
5. **Aggregate language.** Use terms such as "GitHub-reported unique visitor" rather than "person" when interpreting metrics.
6. **Bound raw retention.** Prefer temporary Actions artifacts or external storage with explicit deletion/retention controls.
7. **Minimize secrets.** Keep credentials in GitHub Actions Secrets or another secret manager and grant the narrowest practical scope.

## Public-repository safety check

When running in GitHub Actions, the collector checks the caller archive repository. Unless `ALLOW_PUBLIC_TRAFFIC_ARCHIVE=true` is explicitly set, it refuses to continue if the archive is public or its visibility cannot be verified.

The override exists for advanced users who intentionally accept publication of the data. It is not recommended.

## Interpreting metrics

Clones may be generated by humans, CI systems, agents, indexers or other Git clients. GitHub-reported unique counters are not proof of distinct real-world people. Referrers and popular paths are incomplete top-list data and may refresh on a different cadence from clones/views.
